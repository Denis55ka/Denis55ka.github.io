# denis55ka.app

Статический сайт на Jekyll, публикуется через GitHub Pages из ветки `main`, корень репозитория.
Домен задан файлом `CNAME`; в настройках репозитория должен быть включён Enforce HTTPS
(`.app` входит в HSTS preload, по http страницы не открываются вовсе).

Собранного HTML в репозитории нет — Jekyll собирает сайт на стороне GitHub при каждом пуше.

## Структура

```
_config.yml                                  настройки Jekyll
_data/i18n.yml                               подписи интерфейса, ru/en
_layouts/legal.html                          макет юридических документов
assets/site.css                              все стили сайта
index.html                                   denis55ka.app/
dkonnect/privacy/index.html                  .../dkonnect/privacy/         выбор языка
dkonnect/privacy/ru/index.md                 .../dkonnect/privacy/ru/
dkonnect/privacy/en/index.md                 .../dkonnect/privacy/en/
```

Файлы `.html` не имеют front matter, поэтому Jekyll копирует их как есть, без обработки.

Юридические документы лежат плоско, каждый своим коротким адресом: `dkonnect/privacy/`, дальше
так же встанут `dkonnect/terms/` и `dkonnect/licenses/`.

## Политика конфиденциальности

Эти два `.md` — **единственный источник** текста политики.

### Какой адрес куда подавать

Ни один язык не считается основным. У каждой редакции свой постоянный адрес, а по корневому
адресу лежит страница выбора языка: она показывает две ссылки и заодно перенаправляет
по языку браузера.

| Куда | Адрес |
|---|---|
| RuStore | `denis55ka.app/dkonnect/privacy/ru/` |
| Google Play | `denis55ka.app/dkonnect/privacy/en/` |
| Экран «Настройки» приложения | по локали устройства — `/ru/` либо `/en/` |
| Ссылка «для людей», `x-default` | `denis55ka.app/dkonnect/privacy/` |

**Корневой адрес нельзя подавать в магазин и зашивать в приложение.** Он держится на JavaScript,
и хотя без него остаётся рабочей страницей выбора, юридически указанный адрес должен открывать
сам документ, без промежуточных шагов. Прямые адреса меняться не должны — только содержимое
страниц.

### Как устроен документ

- **Шапка документа** (редакция, дата, пакет, разработчик, контакт) целиком лежит во front matter
  и подставляется макетом. Дата вступления в силу выводится и вверху, и в подвале — но задаётся
  один раз, полем `effective`.
- **Номера разделов не пишутся в тексте.** `## Кратко` превращается в «01 Кратко» средствами CSS,
  счётчиком. Поэтому при вставке нового раздела нумерация не разъезжается, но по той же причине
  порядок разделов менять нельзя, не проверив ссылки вида «см. раздел 8» в тексте.
- **Якоря заданы явно** — `{: #s1}` под заголовком. Автогенерация id отключена в `_config.yml`:
  она давала бы адреса из текста заголовка, и любая правка формулировки ломала бы внешние ссылки.
- **`data-toc`** задаёт короткую подпись для оглавления, если заголовок длинный.
  **`data-mark`** заменяет номер буквой — для Приложения А (в английской редакции это «A» латиницей).
- **Оглавление не хранится нигде** — скрипт в макете собирает его из заголовков страницы.

### При правке текста

1. Обе редакции меняются одним коммитом — они должны совпадать по смыслу.
2. Если меняется состав собираемых данных или получателей — обновите `effective` во front matter
   обеих страниц.
3. Если предыдущая редакция уже была подана в магазин — повысьте `version`.

## Локальный предпросмотр

Необязателен: можно править и смотреть результат уже на опубликованной странице. Если нужен,
потребуется Ruby:

```
bundle install
bundle exec jekyll serve
```

Гем `github-pages` из `Gemfile` фиксирует те же версии, что работают на стороне GitHub, поэтому
локальная сборка совпадает с опубликованной.
